# ADR 0058: Offline Packet Capacity And Qualifications

Status: Accepted offline implementation and measurement, 2026-10-02. The user
approved the next capacity-and-rubric slice after the external review. No provider
call, selector runner, runtime integration or native continuation is authorized.

## Problem And Evidence

The [source-checked review](../../workflows/evals/character_memory_dev/story_continuity/evidence_selection/REVIEW_ASSESSMENT.md)
identified two different uncertainties. Four windows are an explicit count policy,
not a measured consequence of the existing request budgets. Also, the historical
answer-route inclusion signal stays true when a packet gains an unresolved
competing claim. D02's E01/E02 packet contains Monday and Wednesday without the
restoring correction; E01/E07 contains Monday and that correction. Both have the
same positive named-answer signal. Historical availability arithmetic is valid;
using it alone as a settled-answer investment criterion would be the mistake.

## Decision

Permit one narrow counterfactual: serialize **all eight complete D04 exchanges**
into fresh paired generation/reviewer requests, without dispatch. Keep existing
token budgets, full candidate-reply reserve, source validation, persona and empty
saved/local context. Compare the empty and unchanged literal-four controls.
Never prune an oversized whole pool to turn this measurement into a pass.

This explicitly supersedes ADR 0057's rejection of extra final slots **only for
this D04 offline diagnostic**. The runtime rank/admission ceiling remains four;
the proposed model-selection campaign still has at most four final sources.
Use runtime-owned serializers from a separate service-test diagnostic, not a
monkeypatch, runtime parameter or replacement admission policy. Preserve the
hash-bound historical packet builder and all old study bytes. Require byte-exact
agreement with that builder on ordinary in-budget controls.

Clarify prospective assessment at the whole-packet layer. Check both the full
eligible source ledger for material omitted qualifications and the actual final
payload for what is delivered. Answer presence is not sufficient if competing
claims remain unresolved or a supplied genuine correction is concealed. Do not
require every correction in every answer, elect truth by chronology/repetition,
or encode a semantic keyword rule. The [offline protocol](../../workflows/evals/character_memory_dev/story_continuity/evidence_selection/OFFLINE_PROTOCOL.md)
defines fixed D02 witnesses and the rubric before the new D04 measurement.

## Alternatives And Consequences

Do not change `TOP_K`, admission constants, runtime prompts or the H wire format.
Do not refactor the old hash-bound helper and rehash its evidence to match. A
small isolated test helper is intentional duplication of orchestration, not of
the runtime serialization/validation rules; parity checks guard drift.

A full-pool fit would weaken the need for compression in this short fixture,
not prove better answers, production-scale retrieval or a safe larger default.
A failure would locate the binding budget/representation constraint, not prove
that semantic selection is preferable. Record either result without retuning.
Keep source availability, packet interpretation and model behavior separate.

Do not author N01-N03, build provider-attempt orchestration, adopt the proposed
new-case continuation gate or add a model judge in this slice. Those remain
future selector-protocol decisions if that investigation is still useful.

PC-03/04/05/06/09/10/11, historical labels and the native turn-7 stop are unchanged.
The [continuity plan](../plans/character-story-continuity.md#model-assisted-evidence-selection)
remains the delivery entrypoint. Source publication is not deployment or live
authorization. Reassess the next useful step after this bounded result; no further
consultation is needed before a local capacity measurement.
