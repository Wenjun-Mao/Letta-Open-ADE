# ADR 0059: Bounded D04 Behavioral Comparison

Status: User-approved design, 2026-10-02; offline preparation independently
manager-reviewed. Provider execution requires the committed freeze and manager
continuation after effective-configuration and fresh-route prerequisites pass.

## Problem And Evidence

[ADR 0058](0058-offline-packet-capacity-and-qualifications.md) established that
D04's eight complete sources fit both existing budgets. Literal-four supplies
E07's restoration but omits E01, so the restored location is unavailable.
Capacity and source availability do not establish answering or reviewer behavior.
The user selected the recommended separate comparison and said “go”.

## Decision

Prepare three independent fresh generations in fixed order: literal-four
E07/E02/E05/E04; repaired-four E07/E02/E05/E01; whole-pool E01–E08 in original
chronology. Only the last source changes between the first two arms; the third
compares complete-packet policy, with different order and content as well as count.
The repaired arm is an evaluator intervention, not a deployable selector.

This explicitly supersedes ADR 0058's offline-only eight-source exception **only
for this bounded D04 behavioral comparison**. Runtime ranking/admission ceilings,
H contracts and PC-03/04/05/06/09/10/11 remain unchanged. Keep old builders, inputs,
hashes and evidence intact. No new case, selector, store, semantic keyword engine,
model sweep, reroll, native persistence turn or deployment is included.

Use runtime-owned serializers in service-test preparation, then public Model
Router HTTP contracts in the workflow. Pin generation thinking enabled/high,
equivalent to its previously omitted fields under the reviewed router defaults;
reviewer already pins those values. Both use the same model/adapter, 4096 output
cap and 180-second deadline, with no tools, retries or repairs. The reviewer keeps
its JSON format. Reserve the full reply before launch, then measure the complete
actual substituted request without truncation. No embedding or database writes.

Freeze the [protocol and source-quoted rubric](../../workflows/evals/character_memory_dev/story_continuity/evidence_selection/behavioral/PROTOCOL.md)
and exact requests in a clean commit before outcomes. Capture fresh route/config
evidence, immutable stage intent and complete private raw outcome. An uncertain
dispatch consumes its attempt. Six potential requests are the finite design,
not a second spend-policy system. The manager owns readiness review and launch.

## Alternatives, Consequences And Guardrails

Do not infer behavior from offline capacity or restore a selector campaign whose
compactness benefit is unestablished. Do not expand runtime admission to test this
fixture. Explicit equivalent thinking fields remove caller/default ambiguity
without changing product prompts. Tests guard the new request shape and old bytes.

The workflow preserves only final visible text for its own reviewer; independent
lists prevent answer or evaluator leakage across arms. Existing runtime schema
and source-binding validation is an offline audit of captured reviewer output,
not a second factual judge or persistence qualification. Manual assessment separates
supported naming, uncertainty, invention, correction, ownership and naturalness.
One witness per arm cannot estimate reliability or a population causal effect.

Receipt validation does not authorize execution. Earlier complete evidence remains
auditable after a later stopped/uncertain attempt, with per-stage status reporting;
resume still refuses. Reject tampering and non-prefix/post-stop evidence rather
than bypassing validation to permit audit. Manual source-quoted assessment names
the assessor and whether human or AI. A Codex manager's qualitative readout is
AI-authored and must not be described as independent human review.

Keep originals and provider reasoning private. Publish only reviewed synthetic
visible outputs and redacted metadata. Source publication is not deployment or
proof of current provider availability. The [operator entrypoint](../../workflows/evals/character_memory_dev/story_continuity/evidence_selection/behavioral/README.md)
defines stop/resume behavior and isolated launch prerequisites.
