# ADE API

This documentation describes the local ADE API used by ADE Web and operator
workflows.

## Environment assumptions

- Local development defaults:
	- ADE Web: `http://127.0.0.1:3000`
	- ADE API v2: `http://127.0.0.1:8000`
	- ADE-native Agent Studio v3: `http://127.0.0.1:8002`
	- Model Router and Letta: Compose-network services, not host endpoints.
- Browser requests use ADE's same-origin proxy. Direct API clients authenticate
  with the configured reader, operator, or admin Bearer key.
- The stack is loopback-bound and intended for local development. Public ingress
  still requires TLS, managed secrets, rate limits, monitoring, and a deployment
  threat review.

## What this includes

- ADE-native Agent Studio definitions, explicit subjects, conversations, turns,
  typed memories, summaries, runs, and events.
- Archive and restore lifecycle for Agent Studio conversations, definitions, and
  subjects, plus an admin-only fresh-start reset.
- Test orchestration endpoints for checks and runners.
- Stateless Comment Lab and schema-driven Label Lab generation endpoints.
- Prompt, persona, schema, and custom-tool lifecycle endpoints.

## Current Product Direction

The current product milestone is the [Agent Behavior Evaluation Loop](product-roadmap.md):
an operator-facing Agent Studio and Test Center workflow for replaying
conversations, inspecting memory and tool behavior, and making evidence-based
prompt or persona improvements. This is distinct from the
[historical maintenance record](maintenance-roadmap.md).

## Agent Studio lifecycle

Agent Studio separates reusable behavior, user memory ownership, and conversation
history. A session binds one immutable definition version to one memory subject.
Archiving a conversation does not delete its subject memories or definition.

The normal lifecycle is intentionally reversible:

1. Create or reuse an immutable agent definition.
2. Create or select an explicit memory subject.
3. Create, archive, or restore a conversation session.
4. Inspect typed fact revisions and source-message evidence independently of chat.

Key endpoints:

- `GET|POST /api/v3/agent-studio/sessions`
- `GET|DELETE /api/v3/agent-studio/sessions/{conversation_id}`
- `POST /api/v3/agent-studio/sessions/{conversation_id}/restore`
- `GET /api/v3/agent-studio/sessions/{conversation_id}/state`
- `GET|POST /api/v3/agent-studio/definitions`
- `GET|POST /api/v3/agent-studio/subjects`
- `GET /api/v3/agent-studio/subjects/{subject_id}/memories`
- `POST /api/v3/conversations/{conversation_id}/turns`
- `GET /api/v3/runs/{run_id}/events`

Behavior notes:

- Archived resources are excluded from default lists and reject new execution until
  explicitly restored.
- Turns are asynchronous and expose normalized run events without private model
  reasoning or raw provider bodies.
- The native store starts fresh; no Letta importer, dual write, runtime toggle, or
  per-request fallback exists.
- The retained v2 Letta endpoints are a Phase 5 release-level rollback lane, not the
  active browser contract after cutover.

## Error handling shape

FastAPI returns JSON error payloads in the form:

```json
{
	"detail": "error message"
}
```

Common status patterns:

- `400`: invalid request, invalid state transition, validation failures
- `404`: missing resource
- `409`: mutation attempted on archived agent
- `503`: required runtime capability or upstream dependency is unavailable

## Local workflow

1. Regenerate OpenAPI artifact: `uv run python scripts/export_openapi.py`
2. Regenerate Chinese OpenAPI artifact (manual curated): `uv run python scripts/generate_openapi_zh_manual.py`
3. Review missing-term report: `docs/openapi/zh_openapi_missing_terms.json`
4. Add only new/marginal mappings in `scripts/generate_openapi_zh_manual.py` and re-run step 2
5. Update Chinese docs pages manually under `docs/zh/`
6. Validate drift only: `uv run python scripts/export_openapi.py --check`
